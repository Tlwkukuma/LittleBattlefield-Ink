# 项目协作约定

- 2026-09-29 用户明确授权重排首关并选择“紧凑农庄，步兵与载具结合”。`orchard_layout.gd` 是首关运行布局第 3 版：房屋保留原尺寸，围院扩大、南门开口、外围 4.8 m 车道，常规镜头 size=25；此前“首关坐标不改”的约束只继续保护 `data/original` 导入源，不能据此回滚这次已授权布局。`campaign_vehicle_ai.gd` 复用真实上下车、驾驶、弹药和固定武器操作，移动支援车用局部避让，禁止恢复逐步重建步兵网格。按 [首关新布局](docs/orchard-compact-layout.md) 保留有限乘员预约与低频观察预算，仍由用户实际试玩。

- 医疗通过既有 5 / G 轮盘、Tab 医疗按钮与背包“使用”接入真实库存；原骨架叠加 `medical_motion.gd` 的拿取、缠绕 / 开包按压、收回动作，手持道具按手骨定位。按 5 / Esc 或切武器、受击、上车、翻越 / 离地取消，不扣物品；完成才回血与消耗。满血 / 空库存使用图形反馈，保留无倒计时文字的简洁 HUD。原 Tab“医疗演练”由用户主动准备缺血状态，不自动测试。见 [医疗动作](docs/medical-actions.md)。

- 死亡掉落统一使用 `loot_bags.gd` 数据容器与 `loot_bag_visual.gd` 单批次背包，不再生成地面完整枪械；尸体、弹壳、弹匣和爆头掉盔保留。靠近可达背包按 Tab 打开附近 / 随身装备面板，Tab / Esc 关闭；没有可达背包时 Tab 仍进原配装 / 车辆面板。拾取扣除真实余弹和库存，新枪接入现有 1–3 / 战术槽与 G、数字、滚轮切换。隔墙、跨楼层、车内、死亡或攀爬不得拾取。背包最多 128 个，单共享网格，无逐包刚体；仅支持变化才分帧检查落地，禁止恢复逐枪落地模型。见 [死亡背包与拾取](docs/loot-bags.md)。

- 武器快捷切换按用户最新《2077》方向：G 按住六区轮盘，1–3 为自由配装武器位，4 战术、5 医疗，另设收枪区；战术区悬停滚轮切手雷 / RPG 等，松开 G 确认，右键 / Esc 取消。不要恢复四类硬编码或两个主副枪位的旧提案。轮盘关闭 / 失焦 / 重建须恢复时间与鼠标、阻断旧扳机误射；有限弹药、原射击模式和角色实际携带量保留。战斗滚轮循环有效武器槽，跳过空位，不触发医疗 / 收枪；载具 / 固定武器沿用同一 G 轮盘、数字键与滚轮入口，按实际车载武器生成槽位，Q 不再换武器。上下车撤销旧轮盘选择并切换 HUD 槽位，个人装备不被改写。原 Tab 面板负责配装，车辆入口不变，见 [快捷装备轮盘](docs/equipment-wheel.md)。

- 原生 Godot 项目：本目录 `LittleBattlefield-Ink`。演武场入口为 `res://proving_ground.tscn`。
- 2026-09-29 用户另行授权「演武场2」作为无主之地方向样板间：`res://proving_ground_2.tscn` / `START_RANGE2.bat`。它复用同一运行脚本、原骨架及战斗/破坏系统，通过 Tab 与联合演武场互通，F2 仅切换材质表现。原演武场和第一关默认保持原画风；不要把此明确授权扩展成任意另建验收场景。见 [演武场2](docs/proving-ground-2.md)。
- 每次打开 Godot 验收窗口，必须告知用户项目版本、场景及启动时间，并核对实际标题 / 启动日志。唯一构建版本为 `scripts/proving_ground.gd` 的 `BUILD_VERSION`；代码交付时递增，同版本重启以启动时间 / PID 区分。所有入口和展区切换统一使用 `set_game_title()`，窗口标题保留版本、启动时间及 PID；顶部副标题显示版本和启动时间，F5 不改变本次启动身份。不要把 Godot 引擎版本当作项目版本，也不要批量关闭其他任务窗口。
- 统一验收方式：载具、枪械、角色、动作等改动都落实到上述联合演武场，使用已有面板和操作交付用户试玩。不要为单项另建独立网页预览或替代验收场景；载具通过 Tab 的「车辆 / 固定武器」选择和「立即试驾 / 操作」验收。见 [载具外观记录](docs/vehicle-appearance.md)。
- 载具保留封闭驾驶舱。用户在第一次增加约 12% 后再次反馈偏小，七类移动车辆长宽现已再增加约 20%（吉普 3.00×1.82 m，重坦 4.50×2.93 m），不要恢复旧的小尺寸。以原人物约 1.94 m 的含盔身高为固定参照，车体、命中、通行、承托和上下车范围共用 `vehicle_dimensions.gd`。`vehicle_style.gd` 保留与原人物相近的纸感、柔和倒角和疏密适当的墨线；`vehicle_livery.gd` 按场景 `team` 提供我方蓝 / 敌方红涂装，并区分主装甲、浅色面板、深色识别区、钢件、轮履、帆布和玻璃。默认演武场为 14 辆车 + 4 座固定武器成对展示，Tab 选阵营车型，F8 可修改载具阵营。驾驶员仍由封闭舱体遮蔽，详见载具外观记录。
- 固定重机枪和野战炮单独按固定武器处理：操作时显示原角色及双手握持、落地支撑、承力后坐和装填动作，操作员处于武器外侧。它们使用独立的 `emplacement_*` 模块，不套用封闭驾驶舱或上车隐藏人物的规则。见 [固定武器表现](docs/emplacement-presentation.md)。
- 固定武器操作员完成骨骼 / IK 更新后必须递增 `render_pose_revision`，使合批角色与原骨架、命中和遮挡剪影同步；不要只刷新模型根节点而保留走跑骨骼缓存。固定武器、枪口和碰撞使用统一地面高度，操作员按实际操作位地表定位，上下操作位及转向阻挡检查传入真实高度，阴影和脚环同步更新。
- 移动车辆炮塔座、武器枪口和后坐通过 `vehicle_weapon_rig.gd` 与 `vehicle_dimensions.gd` 统一。各主副武器使用独立物理枪口，弹丸、枪口焰、准星和炮尾遮挡检测读取这些节点；外露机枪使用真实抛壳口，封闭炮塔弹壳留在舱内。不要恢复整组武器统一平移或从枪口估算抛壳位置。
- 载具和固定武器弹壳通过 `mounted_cases.gd` 按车型及武器模式显式映射，区分同轴机枪、重机枪、机关炮、榴弹和主炮；同口径保留相近比例。野战炮在真实装填开膛阶段向后退壳，远景壳体缩放有上限。见 [载具弹壳](docs/mounted-cases.md)。
- 载具损毁沿用 `vehicle_destruction_fx.gd` 的两个共享 GPU 批次：最多 256 个动态实例、8 个持续烟火源、每帧 48 个新实例；远处停止生成，残火与余烟限时，空闲关闭更新。保留原殉爆伤害并避免重复通用爆炸特效；焦斑、破损机盖、断履带与炮塔损坏姿态可修复，炮塔显示和碰撞共用尺寸模块并使损毁缓存失效。不要恢复逐碎片刚体或无限冒烟，见 [载具损毁](docs/vehicle-destruction.md)。
- 用户指定《逃离鸭科夫》为后续视角、操作手感、交互、打击感与后坐力表现的主要参考。改动这些系统前阅读 [参考规范](docs/duckov-reference.md)，区分原作已核实事实、本项目设计目标和待实测项。
- 攀爬与翻越动作另按用户要求深入参考 PUBG 的高度分档、助跑动量、双手支撑、提腿和落地重心转移，细节见 [动作记录](docs/prone-and-climbing.md)。沿用本项目 2.5D 镜头及原骨架，不把官方说明当作已获得原版动捕资产。

- 载具操控使用 `vehicle_dynamics.gd` 的平滑起停及赛车式转向：W/S 前后、反向输入先停再倒车，W + Shift 渐进加速，空格为手刹漂移。手刹降低横向抓地，按世界坐标保留移动惯性，松开后渐进恢复；七车型分别配置加速 / 侧滑参数，履带车侧滑较短。无人车使用独立驻车制动，菜单 / 失焦阻断驾驶按键，空中不接受地面驱动力。滑痕与烟尘复用原有界批次。`vehicle_grounding.gd` 共用真实三角地形的接地点、软硬度、车身高度和倾斜；碰撞、承托、枪口、爆炸与下车位置须同步，不能恢复仅允许零高度地面的限制。Tab 地形区入口在驾驶时保留当前车辆，仍由用户亲自试玩。见 [载具驾驶](docs/vehicle-driving.md)。

- 车辆下坡 / 驶出沟沿与爬坡分开判断：轮下接触整体降低且没有向上台阶时，允许跨越暂时超限的接触残差 / 侧倾；坡沿底盘承托仍按真实采样抬高。`vehicle_vertical_motion.gd` 管理重力下落、有界竖向实体扫掠与落地缓冲；车体、枪口、乘员、碰撞共用同一高度，空中不画地面车辙，无人车及空中被毁车辆仍继续落下。不得恢复把向下落差直接当成不可爬坡面的墙，见驾驶记录 v2026.09.28.33。
