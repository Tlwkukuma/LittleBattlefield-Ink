# 炸墙后进入建筑 · v2026.09.29.21

用户截图：联合演武场两层住宅南墙已炸出破口，载具在外侧难以进入。

## 已定位的代码问题

住宅底层有 4 cm 厚实体地板，显示 / 阻挡由 `house_prefabs.gd`、`house_geometry.gd` 统一生成。人物移动已有地板承托与跨小台阶逻辑；载具接地此前仅查询地形、低石与倒木，仍沿室外零高度推进，因而轮履碰撞盒会与地板厚度相交。破口本身已按存活墙格参与人物、载具和射线检测，没有另一张需要移除的整栋建筑碰撞盒。

## 本次修正

- `vehicle_structure_support.gd` 只从现有空间索引取附近存活的地板 / 平台 / 台阶实体，读取实际部件范围与顶面；上层地板高于当前轮履高度加车型台阶上限时不能吸附。
- 轮履接地点、连续履带中间点、底盘采样共用该支撑；地板使用硬地抓地配置。轮履前缘比轴心采样更早接触地板时，计算受车型台阶上限约束的最小抬升，之后仍由原 SAT 检查完整车体，不关闭楼板或墙体碰撞。
- 破口宽度、高度、残留墙格、内部家具以及天花板继续真实挡车。宽度不足以容纳整车时仍需继续炸开；人物使用已有胶囊尺寸及站 / 蹲姿高度判断。
- 轮式悬挂、车下阴影使用同一地板高度；不把室外泥地车辙或雪尘画在室内地板下。上下车位置继续从原实体支撑求解。
- 室内显示本来就是按外墙内侧多边形与人物高度判断，与是否经过门口无关；从破口进入也使用同一剖面显示。

## 性能与范围

每次姿态查询只访问局部候选，不扫描全地图；无刚体、新碰撞节点或寻路网格重建。复用载具单物理帧内的最多 96 个姿态缓存，拓扑破坏修订和接地基准高度变化时失效；已毁地板不继续承托。现有墙体破坏、物理碰撞、射线和人物通行规则保留。

完成必要脚本编译与原入口启动核对。未自动炸墙、驾驶或进行战斗测试，实际破口大小和进出手感由用户在原联合演武场住宅区试玩。
