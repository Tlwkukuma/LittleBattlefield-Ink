# v2026.09.28.38：CPU 热路径、换弹 HUD 与掉落头盔

目标仍为实战稳定 60 FPS、Draw Call 低于 50、尽量保留画面。此批没有宣称已经达到目标，也没有落地全局性能规范。画面和游戏手感仍由用户验收。

## 来自 v37 实战日志的瓶颈

`qa/performance-v2026.09.28.37-20260928-154026.log` 的交火窗口中，物理更新约 9.5–9.7 ms/次，一帧发生两次补算时达到约 19–20 ms。单位约 6.6–6.7 ms/物理次，弹道和载具约 1.9–2.4 ms。渲染帧的角色更新约 3.1–3.2 ms，FX 约 4.8–5.5 ms（粒子运动约 3.2–3.75 ms），换弹时战斗 HUD 重建约 3.53 ms。不能只看 Draw Call 数量推断 CPU 已经足够快。

## 实际改动

- 地形三角采样、碰撞、射线和 AI 避让的高频数学使用明确类型，减少动态 Variant 运算。载具射线先用保守范围排除远处车辆；实际命中仍使用原倾斜分段碰撞体，扩张半径保留原三轴盒扩张的上界。
- FX 的每粒子字典改为 `fx_particle_state.gd` 类型状态；运行时直接调用 `advance_particle`，避免每次积分的重复字典查找。弹壳数量、寿命、缩放、反弹、睡眠和支撑坍塌唤醒保持原规则；弹匣、碎片和烟雾也做了完整循环数学对照。
- 换弹圆环由每帧两条 64 段 CPU 圆弧改为一个持久四边形与 GPU 着色器。原半径、进度、颜色、宽度和鼠标位置继续来自原 HUD；圆环进度不再使整张装备卡片网格失效。仅换弹显示时增加一个绘制批次，启动时透明预热着色器。
- 掉落头盔使用专门的共享网格。原来每个头盔也提交整个人物和五种职业挂件，再在顶点着色器隐藏身体。现在每个掉盔从 117,480 个索引 / 39,160 个三角形降为 21,600 个索引 / 7,200 个三角形（减少 81.6%）；顶点从 91,898 降至 19,104。人物网格不减面，头盔/职业配件不重建外观。专用组仅有可见掉盔时增加两个绘制批次（原色与描边），空组不绘制。
- 首关 `START_LEVEL_01.bat` 调用 `tools/start_level_release.ps1`，每次根据唯一 BUILD_VERSION 构建 Windows Release 后启动原 `proving_ground.tscn` 首关。失败不静默打开旧包。标题额外显示 Release，并保留项目版本、启动时间、PID；默认关闭 Laya。引擎版本仍为 Godot 4.6.3，与项目版本分开。

考察过自然预制体的凸体切片缓存，但本关 nature_objects=0，因此撤回该实验，没有将它计入收益。

## 验证与证据边界

以下都是冻结场景上的资源/数学检查，不操作游戏，不推进 `world.step`，不运行 AI 对战。各日志均检查脚本/着色器错误，而非仅凭进程退出码。

| 检查 | 结果 |
|---|---:|
| `deep_hotpath_contract.gd`：移动、射线、倾斜/移动载具、弹壳、Canvas 几何 | 68,451 项，0 失败 |
| `secondary_performance_contract.gd`：移动、墙格、休眠支撑、血迹、弹坑 | 60,169 项，0 失败 |
| `projectile_unit_index_contract.gd`：弹道人体候选等价 | 68,426 项，0 失败 |
| `deep_render_contract.gd`：头盔三角数据、所有职业/阵营、紧密槽位、完整 FX 循环 | 263,326 项，0 失败 |
| `crowd_batch_contract.gd`：原骨架、头盔绑定、职业切换、可见槽位 | 713 项，0 失败 |

移动对照将“重叠脱困”候选预算固定为足量，以比较相同候选。计时批次排除按微秒截止的脱困搜索，避免不同运算速度改变候选数量而污染比较；没有修改游戏本身的脱困预算。

最新实际启动身份保存在 `qa/performance/latest-release-launch.json`；每次验收日志为 `qa/performance-v<版本>-<启动时间>.log`。
