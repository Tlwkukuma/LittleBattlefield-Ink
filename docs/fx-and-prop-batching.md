# 弹壳、掉落件与场景合批

2026-09-28。用户关闭 Laya 后继续反馈交战卡顿，要求考虑合批 / 烘焙，尤其地面弹壳。仍使用统一 `proving_ground.tscn`；Laya 默认关闭。

## 本轮修改

`fx_instance_batches.gd` 按共享网格和材质建立固定容量的 MultiMesh 池。弹壳、弹匣、碎片、烟火使用轻量位姿节点保存运动状态，共享实例批次绘制；弹匣原来残留的空节点层级也释放。材质、顶点色、描边后续通道、弹壳口径、红 / 绿霰弹壳及各型弹匣形状保留。池内密集排列，过期 / 超预算时交换移除并修正被交换对象的索引。

掉落件停稳后固定当前位姿：不重复上传实例，不逐帧改缩放，不重复计算弹匣重力 / 接地。每种弹壳的镜头可读尺寸共享缓存，只在镜头倍率变化时更新。地表本轮不会实时变形；墙体拓扑版本或车辆位姿变化时使支撑缓存失效，每帧最多检查 16 个休眠掉落件，轮转分摊查询。支撑消失后重新启用下落，移动车体也可使缓存失效。原弹跳、躺平、声音、延迟抛壳与上限（160 壳 / 32 弹匣 / 360 临时粒子）保留。尸体完成原死亡动画并停稳后，也不再重复改根节点和查支撑；环境变化会恢复支撑检查。

`static_prop_batches.gd` 将固定整件树石杂物按 16 m 区域、原始材质参数与图元类型合并。首关 **157 件物件 / 306 个原绘制表面 → 24 个区域 / 48 个合并表面**。所有原顶点、法线、颜色和图元保持；碰撞 / 挡弹数据仍是原独立对象。单件损毁只重建所属区域，区域内其他物件继续存在。按格损坏的墙面和参与楼层隐藏的家具不并入固定批次，沿用原实时网格及切顶逻辑。

MultiMesh 采用整批包围盒，不能逐实例视锥裁剪；因此这里仅用于有严格数量上限的小型效果。大场景固定物件分区烘焙以保留区域裁剪。合批减少提交开销，不等于减少原始三角形数量，也不是把整个战场烘焙成不可破坏模型。接口依据：[Godot MultiMesh](https://docs.godotengine.org/en/4.6/classes/class_multimesh.html)、[SurfaceTool](https://docs.godotengine.org/en/4.6/classes/class_surfacetool.html)。

## 固定工作量测量

同一冻结果园场景放置 160 枚弹壳（4 类）和 32 个 M416 弹匣，先计算落地，再测 180 次更新。世界时间、射击计数始终为零，不运行战斗或模型请求。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| CPU 更新中位 | 1.019 ms | 0.296 ms |
| CPU 更新 P95 | 2.311 ms | 0.522 ms |
| 最大单次更新 | 4.132 ms | 0.606 ms |
| 独立效果绘制对象 / 合批组 | 192 | 5 |
| 静止且支撑未变时的接地查询、位姿上传 | 持续执行 | 0 |

这一工作量的 CPU 中位降低约 **71%**，P95 降低约 **77%**。5 个组保留材质描边，共有 9 个表面通道；这是资源结构统计，不冒充实际整帧 Draw Call。原始结果为 `qa/performance/fx-resting-before.json`、`fx-resting-final.json`，旧代码快照位于 `fx-before-source/`。测量期间其他用户窗口保持运行，耗时不是隔离整机基准。

用户之前无 Laya 的交战日志仍有 13–25 FPS、FX 约 8–12 ms 的片段，保留为 `pre-batching-local-user-play.log`。单位逻辑和弹丸模拟仍有明显开销；不能用上述冻结掉落件基准或暂停帧率宣称整个交战已经达到 60 FPS。

## 检查与交付

- 真 OpenGL 实例池资源 / 运动检查 52 项通过：交换删除、GPU 位姿回读、休眠零查询 / 上传、镜头缩放、支撑下落、车辆缓存失效、360 容量压力与过期清空。无头模式使用 Dummy 渲染器，无法回读真实 MultiMesh 位姿；该检查必须用 OpenGL 运行。它仅操作数学夹具，没有输入或对战。
- 场景分区烘焙检查 349 项通过：全部原图元数、变换后包围盒、墙体独立绘制、实际损毁对象及只更新相应分区。
- 原弹药运动 155 项、84 项装备外观 1410 项、首关执行 12 项、统一入口生命周期 38 项通过。执行检查需 `-- --level01 --no-laya`，否则进入训练场后不适用战斗 AI 的分帧脱困预算断言。
- 左上角 F4 面板新增“特效批次 / 实例”和“特效活动 / 休眠”；性能日志新增 FX 分段耗时与合批统计。
