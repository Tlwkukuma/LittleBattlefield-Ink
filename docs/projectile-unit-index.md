# 弹道人物空间索引：v2026.09.28.35

2026-09-28。落实 [v32 卡顿分析](v32-stutter-analysis.md) 的第一项热点优化。本记录是实现与检查结果，不是待定的全局性能规范。

## 改动

`proving_world.gd` 原先每条非 walls_only 射线遍历全部人物。新增 `unit_ray_index.gd`，在所有人物与车辆移动完成后的弹丸更新阶段，用 4 米格网筛选弹道沿途候选，再执行原来的粗包围盒与精确身体胶囊检测。

- 格网登记原粗包围盒的水平 1.6 米半径，另扩展 0.6 米常用弹丸半径和边界余量；更大弹丸扩大查询格范围。这里是原检测的保守外层，不改变身体或命中体积。
- 候选按原 units 数组顺序排序，保留同距离命中优先级、已穿透命中列表、阵营过滤、头身区域、墙体/地形/车辆遮挡。原 GLB、骨骼、动作、材质和画面不变。
- 仅在弹丸阶段首次需要人物查询时建表。少于 4 个弹丸或 12 个单位时直接扫描；新生弹、手雷和迫击炮如果没有人物查询，不建表。
- 索引在该阶段结束后失效。镜头拾取、AI、交互、菜单瞬移等阶段保留即时扫描，避免使用旧位置。弹丸阶段内车辆损毁强制下车的所有成功出口调用 `index_unit` 同步人物位置；原移动/车辆推挤接口也同步。
- 性能日志新增 `unit_ray_totals`，记录每个报告区间的射线数量、候选数量、原全扫描候选数和累计构建耗时；仅开启性能日志时计数。
- `physics_per_frame` 记录两次主场景帧回调之间累积的物理耗时；`physics_steps_per_frame` 记录 0/1/2/… 次物理更新对应的帧数。`worst_frame_interval` 保存最长区间的物理总量、次数、父回调耗时。子回调 `last_ms` 仍是之前回调值，不能据此拼出精确整帧 CPU/GPU 总耗时。
