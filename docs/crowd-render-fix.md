# 头盔与职业挂件发黑修复 · v2026.09.28.31

用户提供的 v30 首关截图显示头盔变为整片深紫、职业背包发黑。原模型与颜色数据未被修改；错误来自本次角色合批的实例颜色初始化。

`crowd_batches.gd` 使用自定义实例数据，但此前没有启用并显式初始化实例颜色。在本机 Godot 4.6.3 Compatibility 路径上，原网格的 `COLOR` 被零实例颜色相乘：蓝方头盔进入原材质的深色墨线分支，职业挂件接近黑色。修复为分配时启用 `use_colors`，并给全部 128 个槽写入白色；复用、剔除、尸体、掉盔使用相同中性颜色，不增加绘制通道。红蓝纸色也从原材质参数读取，避免另写一份颜色常量。

引擎实现可核对 [GLES 场景着色器](https://github.com/godotengine/godot/blob/4.6/drivers/gles3/shaders/scene.glsl) 的顶点色乘实例色，以及 [MultiMesh 存储](https://github.com/godotengine/godot/blob/4.6/drivers/gles3/storage/mesh_storage.cpp) 的颜色/自定义数据共用布局。错误在本项目实例初始化，未修改引擎。

另修复用户真实试玩日志暴露的节点生命周期问题：换装移除旧节点、但尚未释放时，刚性/矩阵合批先检查 `is_inside_tree()`，避免调用离树节点的全局变换并反复报错。

验证：

- `qa/crowd_batch_contract.gd`：713 项通过，新增三种姿势的原头盔位置、盔壳/色带/边沿颜色检查。导入骨架初始延迟设置完成后再比较挂接矩阵。
- `qa/crowd_appearance_contract.gd`：真实 OpenGL 下，在冻结的原首关入口数值比较原材质与合批结果，显式零颜色作为负对照。头盔偏差总量从负对照 981272 降为 10121；挂件从 1162654 降为 259。不是逐像素完全相同，也不代替用户外观验收。未保存截图、操控游戏或推进战斗。
- `qa/render_batch_lifecycle_contract.gd`：10 项通过，覆盖节点暂时离树、重新加入和释放。
- `qa/helmet-fix-draw-budget.log`：24 / 39 / 48 / 48 Draw Call，原资源组合检查通过。

性能规范没有落地。v30 用户真实首关交战日志已出现 68–76 Draw Call、约 51.47 有效 FPS 的五秒区间；资源检查数值不能代替这一失败结果。用户后来切回训练场的数据也不能混入首关结论。实战 50 以下 / 稳定 60 目标仍未通过，此修复只证明头盔颜色初始化和节点生命周期回归得到处理。
