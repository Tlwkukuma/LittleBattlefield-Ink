# 首关 AI：Laya 指挥与三轮迭代

2026-09-26。用户本次明确授权三轮自动测试，每轮分析后迭代；该授权覆盖此前仅由用户试玩的偏好。本轮不重做角色、枪械、载具资产，不改变第一关双方总兵力及胜负规则。

## 依据

旧项目 `docs/laya-ai.md`、`docs/lan-diagnostics.md` 与实际 `LayaTacticalAdvisor.mjs` / `LayaCommanderDoctrine.mjs`：低频模型选择合法战术候选，导演分配小队任务，单位层执行感知、掩体、移动和开火。真实物理、命中和破坏仍由 Godot 决定。

本机 `127.0.0.1:8765` 已有健康服务，RTX 3060、CUDA FP16；直接复用，不下载或重新启动第二份模型。只有实际成功的决策响应才计作模型调用，失败、过期或低置信度必须明确记录。

## 测试协议

共三轮，使用相同首关、随机种子、30 Hz 固定模拟步长，每轮最多 120 模拟秒或至胜负。保留初始 60 人与双方 120 总兵力。玩家静置且不射击，倒地后按原规则接管并继续静置；这不能代表真人胜率。

逐轮保留真实事件、每两秒状态、指挥观测与响应、推进/卡住指标及步进耗时。采用真实时间运行，避免加速模拟使正常的异步 Laya 响应被误判过期。测试使用世界模拟的解析枪口和命中几何，不包含骨骼动画枪口、客户端渲染、音效或 GPU 帧率。

- 第 1 轮：原有规则 AI 基线，随后分析并接入指挥/战术改进。
- 第 2 轮：真实 Laya 与新执行层，随后按日志修正任务、通路和交火问题。
- 第 3 轮：相同协议复测，分析遗留问题并完成必要收尾；不追加第四轮对局。

基线源码留存于 `qa/ai-review/baseline`。以下结果在每轮结束后填写，不能把编译检查或模拟估计当作已发生的对局。

## 接入契约

- 本地 `campaign_commander.gd` 仅处理合法候选、串行请求、超时和校验；`campaign_director.gd` 管理蓝红双方独立指挥轮次与稳定小队；`campaign_ai.gd` 负责物理世界内的执行。
- 每次先请求风险、机动、编制、路线政策，再逐队请求任务。后续队伍可以看见已分配的任务数量。完整轮次结束后等待四秒；两次请求至少相隔 200 ms，实际发出后 12 秒超时，十模拟秒以前的观测不能生效。
- 仅用己方兵力/补员、公开据点状态和近期感知报告，拒绝读取隐藏敌人的即时位置、健康或弹药。附近枪声允许生成带误差的低置信报告；实际射击仍要求当前目视与三维遮挡校验。
- 任务候选为占点、守点、前沿警戒、火力掩护和预备。沿用原 Laya 的枚举决策与证据权重方法，路线词汇按本图调整为道路、西丘、西壕、分路与快速反击；本图没有另造东侧路线。
- 健康接口在线不等于模型决策生效。日志分别保留真实 POST、原始选择、置信校验、应用选择、软权重、超时/过期/低置信拒绝。没有合法模型任务的小队使用规则任务；请求失败或低置信度不会覆盖已接受的合法命令。超过四十秒未更新仅标记命令陈旧，界面注明沿用已有命令。
- 吉普和两挺固定武器仍由玩家操作，本轮不把无乘员载具计作可用装甲编队。解析枪口测试不能替代实际骨骼枪口、渲染帧率与操作手感验收。

## 第 1 轮

已完成，原有规则 AI。固定种子 33003，90.30 模拟秒 / 90.02 墙钟秒，按正常胜负提前结束。蓝方阵亡 120、红方 96，蓝方失败；双方预备耗尽，红方存活 24。4077 次射击、984 次伤害事件、77 格破坏。

蓝方从未进入 B 点；红方 24 个单位槽曾进入。蓝方 14 个单位槽经过负海拔沟道，8 个单位槽经过西侧高地，说明通路可用，但现有路线推进未完成占点。槽位会被补员复用，这些数字不是经过的人次，也不能解读为三轮真人胜率。

蓝方距 B 的中位距离由开局约 27.1 m 增大到 20 秒时约 41.45 m；该统计也受前沿阵亡和南侧补员影响，不能单凭它认定同一士兵倒退。结合基线代码从路线首节点加入的逻辑，确认前沿或侧翼出生的单位存在回走绕行风险。修复从当前位置加入合理后续路段，同时保留院门前的必要接近路线。

模拟步进 P50 / P95 / P99 为 27.15 / 38.62 / 63.14 ms，最大 200.52 ms。导航更新曾占用 50–103 ms；第一轮慢帧中的 nav_ms 是最近一次更新耗时，不能据此认定每个慢帧都由导航导致。第二轮起另加当步分段计时。记录器的“有移动请求但连续两秒实际低速”指标为零；它不能排除空路径导致根本没有移动请求的停滞，需结合状态样本分析。

第一轮后的迭代：接入独立双阵营 Laya 指挥、稳定小队任务和观测隔离；加强占点与火力掩护的分工、真实视锥与三维遮挡、掩体和压制执行、空路径恢复。导航从一次更新全部局部网格，改为每帧六个节点/边的分阶段更新；未更新节点禁用，完成后与整图逐节点逐边一致，248 项几何检查通过。对局源码哈希与原始事件见 `qa/ai-review/round-1`。

## 第 2 轮

已完成，真实 Laya + 新执行器。运行 120 模拟秒 / 126.33 墙钟秒。174 次真实 POST、174 次有效模型响应，264 个政策/任务答案通过置信校验，131 次小队任务生效，传输错误为零。请求到响应中位 107 ms，模型响应记录为 CUDA FP16；首批简报未截断。

效果不合格：蓝方 119、红方 67 人阵亡；蓝军仅余静置玩家，蓝方仍未进 B。蓝方 20 秒距 B 中位数已由基线 41.45 m 改善到 26.76 m，路线倒退有所修复，但战术分工退化：蓝方 37 次模型小队任务全部为 attack，没有形成火力掩护。红方保留 attack / hold / control。

步进 P50 / P95 / P99 为 15.80 / 48.73 / 59.60 ms，最大 169.19 ms。后半局蓝方没有 AI 交战，整体 P50 下降不能当成性能提升结论。分段计时确认最大尖峰主要在单位执行（167.91 ms），而非 Laya HTTP（0.023 ms）；导航拆分已避免之前的大块更新，但个别边批次仍达 17.97 ms。

第二轮后的迭代：提高重复进攻任务的机会成本，并依据缺少掩护/警戒的情况校准模型候选概率，保留原始和应用选择；没有可指挥 AI 的阵营不再空发请求。失败射击增加短重试间隔并先检查朝向；视觉预算轮换且保留已确认目标，避免墙后最近十人永久遮蔽侧翼敌人。恢复原有新目标反应窗口；脱困不再反复执行多层邻格搜索，新增四毫秒局部搜索限额；昂贵导航边批次减为三个。

前沿样本显示，多名蓝军仍有有效路径并以 2.3–2.8 m/s 抵近，在距 B 7–10 m 处被击杀；零入圈不能归因于普遍卡路。远处掩护队继续前往支援位置；近点直达阈值由 16.5 m 收紧到 7.5 m，加入路线时保留最后的院门接近段；只有据点正在争夺时才提供快速反击候选。

## 第 3 轮

已完成，120 模拟秒 / 128.18 墙钟秒。**本轮 Laya 服务不在运行：实际 POST 与模型响应均为零，发生四次连接超时及三十七次退避拒绝。** 测后健康接口拒绝连接，未找到 Python 服务进程；仅凭现有日志不能确定进程退出原因。第三轮实际检验的是新执行层与规则兜底，不能作为新模型分工策略通过对局复测的证据。

蓝方 119、红方 84 人阵亡，蓝方仅余静置玩家，红方存活 30、预备 6，仍为 playing；这不是蓝军取得胜利。蓝方仍零入 B，红方 28 个槽进入；蓝方 10 个槽经过壕沟、4 个槽经过高地。蓝军最近状态采样距 B 中心 8.11 m，未达到 4.5 m 占点圈。

规则兜底的分工持续存在：20.23 秒蓝军 27 名 AI 为 19 进攻 / 6 掩护 / 2 警戒；40.37 秒为 18 / 7 / 2；60.70 秒还有 20 名 AI，为 14 / 5 / 1。相比第二轮约一分钟已耗尽蓝军 AI，交火持续更久；但同一时间段伤亡仍高于原规则基线，不能称全面改善。

整局步进 P50 / P95 / P99 为 27.30 / 48.94 / 56.84 ms，最大 105.28 ms。第三轮首次完整保存逐帧耗时，前 60 秒 P50 / P95 / P99 为 36.87 / 52.02 / 60.36 ms，最大 83.40 ms；1800 帧中 1181 帧超过 33.33 ms。最大整局尖峰来自单位执行，不能归因于当步为零的导航更新。前两轮缺少完整逐帧数组，无法严格比较同一交火时段分位数；这些数据也不是渲染 FPS。

第三轮后的收尾迭代：恢复独立运行的本地 CUDA FP16 侧车；`START_LEVEL_01.bat` 调用 `tools/start_laya.ps1` 复用健康实例，无实例时从现有模型启动独立后台进程。仅加载本地文件，禁止联网补下载，不再依赖旧网页战斗服务器的生命周期。已有端口被占用时等待健康，不终止占用者或重复加载模型。界面明确区分“Laya 离线 · 规则指挥”和“连接中断 · 沿用已有命令”。

恢复后另做**冻结场景接口检查**，没有第四轮对局：`simulation_time=0`、`shots=0`，四次真实请求全部成功，GPU CUDA FP16，简报未截断。蓝红各一次政策与一次任务请求；在测试夹具“多个小队已全部进攻”的状态下，原始 attack 经完整候选概率校准后应用 support，验证接收、校准与任务应用链路。它不能代替动态攻点效果复测。记录见 `qa/ai-review/post-round-connection.json`。

## 当前交付边界

- 真实 Laya 接入已证实：第二轮 174 次模型响应；恢复后的冻结场景四次响应。第三轮的离线失败保留原始日志，不修改为成功记录。
- 已实现观测隔离、分队指挥、火力掩护、三维遮挡与坡沟寻路、失败重连和状态提示。协议 29 项、导演 48 项、执行 14 项、导航增量一致性 248 项检查通过，均不额外推进对局。
- **攻点效果尚未达标**：三轮蓝军均未进入 B；不能宣称首关攻防平衡已验证或模型战术优化全面通过。下一次真人试玩应重点看南侧接近段火力、掩护位置与玩家协同；本轮按用户要求停止在三次对局。
- 当前保留原兵力、配装、补员、接管与占点规则。车辆及固定武器仍由玩家操作；自动载具乘员、AI 手雷攻坚与完整动画枪口/渲染性能不在本轮已验证范围。
