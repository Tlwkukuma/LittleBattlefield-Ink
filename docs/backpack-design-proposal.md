## 推荐规则

### 容器与装备

采用统一格子、堆叠和总负重。第一版用一种 16 格背包，物品或一组堆叠占一格，提供自动合并与整理。暂不引入旋转物品、形状拼图、背包套背包。

| 部位 | 用途 | 容量 / 重量处理 |
| --- | --- | --- |
| 快速武器 A、B | 均可装备步枪、狙击、霰弹、冲锋枪、手枪或发射器 | 各一件；计入总负重，不占背包格 |
| 近战挂点 | 军刀、斧、长刀等，可留空 | 一件，计入总负重 |
| 背包 | 备用枪、弹药、投掷物、医疗 / 工程物品 | 任意搭配，受格数与负重约束 |
| 投掷快捷入口 | 选择背包中的投掷种类 | 仅引用已有物品，不凭空增加容量或数量 |

快速武器位可全部留空，背包允许装满投掷物。只有两个快速枪械位；背包里的第三把枪须打开背包替换其中一件，完成较慢的取放动作。背包中多带枪的代价是重量、格子、弹药占用与取用时间。两把主武器完全合法；手枪则通过轻重量、较快拔枪保留用途。

初始调参建议：普通手雷每格 2 枚，常规弹药每格 30 发；火箭弹、特殊大件单独设上限。物品定义显式配置重量与堆叠数，避免所有口径共用同一个上限。18 kg 以下正常移动，18–24 kg 平滑降低冲刺速度，最多约 15%；超过 24 kg 拒绝新增携带。数值仅为起始调参，不代表现实重量或参考游戏参数。

### 键位与 UI

| 输入 | 处理 |
| --- | --- |
| 1 / 2 | 取出快速武器 A / B，允许双主武器 |
| 3 | 近战挂点；空位不自动发装备 |
| 4 短按 | 取出上次选择的投掷物，保留原有左键预瞄 / 松开出手、高低抛 |
| 4 长按 | 显示小型投掷选择盘，只列出实际携带种类及数量 |
| I | 打开背包；第一版保留现有 Tab 武器 / 载具面板及试驾入口 |
| E | 拾取、打开地面包或补给箱；F 仍是载具操作 |

背包窗口三部分：附近物品、随身背包、快速装备位。支持拖放、双击装备 / 转移、拆分堆叠、一键整理；丢到地面区域才丢弃，拖到无效位置不产生变化。背包满、交换失败时保留原物品。切小背包时必须先解决容量溢出，禁止静默销毁。

背包打开时阻止射击和其他战斗输入透传，并取消尚未投出的手雷；已投出的手雷继续原物理过程。关闭界面不能因仍按着鼠标而误射。演武场可沿用菜单暂停，正式战斗打开背包不暂停世界。

战斗 HUD 仅显示 1–4 图标、当前高亮及必要数量；详细重量 / 名称放背包界面，不增加“切换成功”等浮框或多余文字提示。

### 弹药和动作

- 每把枪拥有独立实例 ID，即使两把都是 M416，也各自保存弹匣余量与射击模式。背包、挂点和地面容器之间只迁移这个实例。
- 备用弹药按可兼容的弹药类型存放在背包中；同弹种枪支共享真实弹药堆叠，切枪不补弹。口径相同但弹药不兼容的装备不能误用。
- 空仓自动装填保留，只有背包确有兼容弹药才能装填。弹匣内弹药和背包散弹只记一次重量。
- 第一版继续使用现有整枪装填机制；抛壳及掉落弹匣特效保留。掉落的表现弹匣不作为第二份可拾取弹药，避免复制资源。逐弹匣库存可后续单独设计。
- 切枪取消未完成的连发、近战和未出手投掷；被取消的换弹不增加弹药，已消耗的弹药不退回。保留原骨架，补收枪 / 取枪过渡及开火窗口。
- 投掷物在实际出手时扣一枚；取消预瞄不扣。相同种类还有库存则继续取用；耗尽后回到先前有效武器，若没有则空手，不自动改扔其他种类。
- 换枪、死亡、拾取、进出载具、接管友军均走同一库存状态。驾驶时 1–4 不覆盖车载武器，Q 保留原功能。

### 可形成的配装

| 配装 | 携带举例 | 取舍 |
| --- | --- | --- |
| 双枪泛用 | M416 + AWM，兼容弹药，少量手雷 | 应对距离广，重量与弹药格占用较多 |
| 投掷专精 | 武器位留空或只带手枪，背包多装手雷 / 烟雾弹 | 遮蔽与爆破能力强，持续直射火力弱 |
| 轻装突击 | 冲锋枪，有限弹药与医疗物品 | 机动性好，续航和远距离能力有限 |
| 工程支援 | 步枪 + 发射器，火箭弹与维修工具 | 反载具能力强，重量和补给压力大 |

职业挂件和技能继续区分职业，第一版无需用职业强制锁死可携带枪种。

## 当前代码差距

- `scripts/proving_world.gd` 的 `inventory[weapon_id]` 目前是按枪型缓存弹量与模式，不是完整背包；无法表达两把同型号枪的独立状态、实际弹药堆叠和有限携带量。
- `scripts/campaign_rules.gd` 的 `loadout` 是预设武器 ID 列表，需迁移成装备实例和容器；接管友军时继承其实际库存，不能复制上一名角色物品。
- 原模型、枪口、弹丸、抛壳、掉落弹匣和 `weapon_fire_control.gd` 的射击模式可以复用，由新的库存层提供当前装备与弹药消耗接口。
- 建议分成物品定义、武器实例、容器转移 / 堆叠、角色装备与快捷引用、背包 UI 五部分。容器转移要原子完成；重量在物品变化时重算，UI 用变更事件刷新，不为每个 AI 每帧遍历所有库存。
- 地面掉落使用一包多物品数据与一个可交互实体；装饰弹壳继续用原有批次 / 生命周期，不将每颗弹药或弹壳变成长期刚体。50 vs 50 的实际性能仍待实测。

## 落地顺序与验收

1. 同一联合演武场先完成物品实例、16 格背包、双快速武器位、1–4 切换、弹药堆叠 / 消耗、I 界面和投掷物选择。原 Tab 面板作为演武场物资来源，遵守背包容量；载具入口保留。
2. 接入 E 拾取、丢弃、补给箱和死亡掉落；让“配装 → 战斗消耗 → 拾取补给 → 再战”闭合。同步迁移关卡预设、AI 配装与接管库存；整理装备不能生成额外资源。
3. 根据用户体验调校负重、取放动作和堆叠上限，再扩展背包型号、医疗 / 工程物品和车辆储物。

必要逻辑检查：同型号双枪独立余弹、同弹种共享库存、无弹不装填、满包交换回滚、取消投掷不扣数量、出手只扣一次、移交 / 丢弃 / 拾取不复制、窗口操作不误射、空槽 / 驾驶 / 死亡时按键处理。手感和画面仍由用户在 `res://proving_ground.tscn` 亲自试玩，不自动操控游戏验收。
