# 《逃离鸭科夫》参考规范

用户于 2026-09-26 指定该游戏作为后续修改的主要参考，范围包括视角、操作手感、交互方案、打击感及后坐力表现。美术继续采用本项目的胖乎乎小兵和线稿风格，玩法继续保留小小战地的陆战、载具、可破坏场景及大量单位。

- 本机目录：`F:\steam\steamapps\common\Escape from Duckov`；`Info.ini` 标记版本 `2.3.30`。

- 对本机 `Duckov_Data/Managed/TeamSoda.Duckov.Core.dll` 做只读符号检查，发现 `GameCamera`、`CameraArm`、`AimTargetFinder`、`ADSAimMarker`、`DisableCameraOffset`，以及 `InteractHUD`、`InteractSelectionHUD`、`MultiInteractionMenu`。这只能证明这些功能结构存在，不能据此断言默认镜头倍率、实际键位或目标选择规则。
- 后坐相关符号有 `StartVisualRecoil`、`UpdateVisualRecoil`、`AimRecoil`、`ProcessMousePosViaRecoil`、`RecoilHMin/Max`、`RecoilVMin/Max`、`RecoilRecover`、`RecoilRecoverTime`；命中与镜头反馈有 `PostHitMarker`、`HitMarker`、`hitFX`、`hitFX_NoBlood`、`CameraShaker`、`CameraShakeTypes`。据此可参考其把视觉后坐、瞄准偏移、恢复、命中和镜头震动分别组织的思路。各数值、调用顺序与实际强弱尚未实测。
- 未修改原游戏文件或存档，未将其模型、音频、程序集或素材导入 Godot。没有从未核实的字段名编造原作参数；没有把第三方第一人称 MOD 当作原版参考。

## 本项目采用的设计目标

以下是结合用户要求制定的实现准则，不是对原作行为逐项复刻的声明。

| 系统 | 参考方向与本项目落地要求 |
| --- | --- |
| 镜头与狙击 | 保持统一俯角与朝向。按 9 月 28 日澄清，常规视野固定，按住右键拉远扩大可见战场、松开恢复；狙击也先扩大范围，再淡入跟随鼠标的圆形遮罩。鼠标按屏幕位置瞄准，缩放不突然换坐标系，不追随每次后坐落点，不强制居中目标。 |
| 移动与持枪 | 移动方向和瞄准方向解耦，起停有重量但输入及时；快跑、举枪、装填、蹲伏、卧倒和翻越的衔接连续。继续用用户原骨骼及原走跑动画。 |
| 三维选点 | 鼠标指向可见部位或墙面时先确定三维高度，再计算枪口方向；脚、墙根、墙顶、室内均有一致规则。按用户最新要求，屏幕准心始终跟随鼠标，不受掩体、枪口摆动或后坐落点牵动，也不再显示遮挡变色/提示；实际弹道和墙体碰撞保留。 |
| 交互 | 优先当前可达且高亮的一个目标；名称、动作、按键、进度放在对应目标附近。多个目标重叠时提供明确选择；短按即时动作与长按持续动作区分。背包、武器库、编辑器等 UI 不透传开火。按用户最新指定，战斗模式 E 用于通用交互，F 用于上下车及固定武器操作位；这些键位是本项目选择。 |
| 枪械后坐 | 分为枪身向后冲量与抬升、肩膀/上身承力、真实瞄准偏移三层。点射迅速产生冲量，随后恢复；连射累积但能压枪。不同枪支的首发、后续上扬、横摆、停火恢复分别调节，不能全枪只乘一个震动系数。 |
| 镜头后坐 | 保持战场空间稳定，镜头反馈克制且可单独调节；不得用持续大幅镜头摇晃替代枪身承力和弹道后坐。按用户最新要求准心固定在鼠标位置，散布只影响大小。若引入震动，需避免在鼠标静止时引起三维选点循环漂移。 |
| 开火反馈 | 扳机、枪口火光、枪身冲量、枪声瞬态、弹壳抛出同步；区分单发狙击、连发步枪、冲锋枪、霰弹及发射器的节奏。弹丸从实际枪口出发，保留用户要求的可见尺寸。 |
| 命中与打击感 | 将开火和命中分开；金属、砖石、木材、人体、护甲反馈有差异。命中标记、短促音效、方向受击动作与少量局部粒子共同表达冲击；连续命中合并动作，不能每发都重播完整受击或冻结全场。 |
| 重击与死亡 | 爆头、致命命中、爆炸和普通命中分级表现；保留帽子击飞、按来弹方向选择原受击/倒地动作、武器掉落和场景破坏。反馈有强弱但不能遮住后续目标。 |
| 性能 | 对弹壳、命中碎屑、尸体、音频并发分别设限与复用；50 vs 50 时优先保证输入、弹道和目标可见。按 9 月 28 日确认，普通弹用单批次短光迹，不保留长路径历史或逐弹灯光。使用原有单次世界渲染。 |

## 迭代顺序与当前状态

1. **已实现，待用户体验：同视角圆镜与右键扩大范围。** 9 月 28 日修正此前拉近的实现：普通状态固定，右键扩大主相机范围，狙击先扩大再出现圆镜。狙击可选常规视野宽高的 1.25 / 1.5 / 2 / 2.5 倍，默认狙击 2 倍、精确射手 1.5 倍。相机投影与输入状态检查 72 / 72 通过。没有第二次世界渲染，实际手感由用户验收，见 [方案](circular-scope.md)。
2. **下一项：后坐表现对照。** 用现有 M416 / AKM、Vector、AWM 和霰弹代表枪，分别对照单发、三发点射、连续射击、停火恢复、移动与卧倒。重点检查枪身冲量是否可见、肩膀是否承力、实际弹道偏移是否可控；准心按最新要求始终跟随鼠标，原有伤害、射速和弹药设计继续保留。
3. **随后：打击感对照。** 人体、护甲和墙材质的命中反馈分层；原方向受击动作、致死动作与物理冲量衔接；开火声与命中声的时序及连发混音不能互相淹没。
4. **随后：交互统一。** 在演武场的载具、武器、门、室内遮挡与场景编辑流程中逐项落地目标提示及操作规则。

用户负责实际游玩验收。代理完成必要静态、资源、数学和启动检查后打开演武场，不自行模拟原作体验，不宣称已经复现未经测量的后坐参数。后续记录应写明“参考观察 → 本项目调整 → 已验证内容 → 用户反馈”，而不是只写“更像鸭科夫”。

## 枪械与弹药外观（2026-09-26）

已结合本机资源元数据及 PUBG 官方枪型展示，接入枪型比例、材料分区、弹种外观、红/绿霰弹壳及对应掉落弹匣；将霰弹丸与整枚弹壳分开绘制。参考证据、设计尺寸与验证边界见 [枪械表现记录](weapon-presentation.md)。本次没有修改后坐力和原弹道散射参数，也没有将本地网格包围盒当作原游戏的世界尺寸。

后续沿渲染器绑定核实：普通 `BulletNormal` / `BulletSMG` 预制体使用暖色短轨迹，`ShellEmitter` 则使用不发光网格粒子抛壳。特殊弹的 Capsule 不能代表普通弹，海贝物品的 `Shell` 网格也不能用作弹壳尺寸依据。9 月 26 日版本沿用单网格实体外观，9 月 28 日用户明确选择短促亮芯＋很短光迹，并要求缩小弹壳、按枪械弹种分尺寸。最新实现见 [短光迹与弹壳](bullet-flight.md)，早期证据见 [弹药体验](ammo-experience.md)。
