# v2026.09.30.53 联机同步定位与修复

## 已定位的问题

用户确认双方运行 v52；客户端截图显示 75 FPS，房主流畅，队友动作仍慢。帧率不能代表输入到权威状态回传的延迟。

1. `unit_step_schedule.gd` 只把 `unit.player` 视为每帧更新的人类。房主接管的远程士兵带 `network_peer_id`，却被放入交错的 30 Hz AI 调度；人类移动分支仍用单帧 `delta`，漏掉一半移动与加速度更新。直接运行相同世界、相同起点和输入 60 帧：v52 房主走 2.706 m，队友走 1.006 m；v53 两者均走 2.706 m。
2. 客户端发出控制后完全等房主回包才呈现自己的动作；高 FPS 也不能消除此往返等待。
3. v52 多个运动分包和不同大小的特效共用不可靠有序 RPC。运动实体分包相互独立，迟到的某个分包不应该因另一实体分包先到而被整个丢弃。Godot 官方说明了此模式在不同大小包上的丢弃行为：[高层网络通道说明](https://docs.godotengine.org/en/4.6/tutorials/networking/high_level_multiplayer.html#channels)。
4. 可靠完整快照每 0.1 秒继续发送，丢包时累积过时状态；客户端时间和动画又过度依赖快照。弹体网络插值误用本地物理帧插值比例，在同一网络区间内重复起播。

## 实施

- 远程人类与房主人类都按 60 Hz 更新；AI 保持已有交错调度。
- 新增 `LanSession/Realtime`：输入走独立通道 2 的不可靠有序 RPC；30 Hz 权威自身状态和远程运动走通道 1 的不可靠 RPC，每个实体用房主时间拒绝旧帧。保留原父节点 RPC 签名以兼容旧版。
- 队友使用原 `soldier_traversal.gd` 与真实场景碰撞计算本地移动、朝向和动作呈现。房主实际应用输入后回传序号，客户端据此重放尚未确认的输入并平滑校正；最多保存 30 帧，偏差大于 1.5 m 或接管对象变化时直接重置。碰撞测试证明不能穿过石墙；不覆盖权威坐标、伤害、命中、弹药或破坏判定。
- 固定武器 / 载具瞄准立即在独立呈现字段更新；炮塔权威状态与射击仍由房主计算。退出、下车、死亡接管均清除旧呈现字段。
- 每位新版队友最多有一个完整可靠快照在途。输入携带收到的快照序号；等待确认期间合并为最新世界，保留按队友的破坏和背包修订，避免持续堆积旧快照。
- 数据报序列化预算 1100 B；异常大自身状态压缩为 700 B 内容片段。乱序片段可复原，缺片不应用；组装最多 8 帧、250 ms。常规实测最大 972 B，最终战斗回归最大 1036 B，均小于 ENet MTU。
- 静止远程实体只在变化或 0.25 秒心跳时发送。相同空闲 AI 基准的运动发送量由节流前 2,771,136 B 降至 956,628 B；此数值只代表该基准，不能代表全员运动的战斗带宽。
- 客户端视觉时钟按实际经过时间前进，最多领先最新房主时间 0.2 秒；弹体在收到的两个权威采样之间用单调时间插值。
- Debug 显示输入回声 P50/P95、自身更新间隔 P95、当前断档和本地预测状态。输入回声含传输、排队和房主应用时间，不等同纯网络 ping。

## 相同网络条件的对照

使用两个独立 Godot 4.6.3 进程和本地 UDP relay；每方向 35±12 ms 延迟、5% 数据报丢失，并在第 8–9 秒完整阻断下行。v52 使用已发行冻结 PCK；v53 使用修改后的同一原生项目。双方 AI 关闭，16 秒交替移动 / 停止，九次移动起步。测试不修改真实网卡或系统网络规则。

| 指标 | v52 | v53 最终发送节流版 |
| --- | ---: | ---: |
| 本地移动呈现响应 P50 | 253 ms | 当前物理帧内 |
| 本地移动呈现响应 P95 | 693 ms | 当前物理帧内 |
| 断流恢复后权威自身状态落后 P95 | 383 ms | 67 ms |
| 全程权威自身状态落后 P95（含 1 秒断流） | 433 ms | 267 ms |
| 含断流及预测领先的呈现位置与最新遥测位置差 P95 | 0.160 m | 0.394 m |

本地响应记录 v53 为 0–1 ms，测量位置是在提交输入的同一物理帧内，**不是实际屏幕或端到端 0 ms**。预测使画面领先收到的权威状态，因此最后一行差值增大；它混合了预测领先、遥测采样时间差和断流，不能当作同时间坐标误差。真实命中位置仍是房主坐标。最后一次输入回声 P50/P95 为 107/120 ms，自身更新间隔 P95 为 67 ms；网络等待仍存在。

证据：`qa/latency-v52-final-client.log`、`qa/latency-v53-cache-client.log`、`qa/latency-v53-cache-host.log`。更详细的本机早期运行在 `qa/latency-v53-final-*.log`。
