# v2026.09.28.32：多人运动与交火卡顿处理记录

本文件记录本次实现及证据，不新增用户暂缓的项目性能规范。

## 已知现象与证据

用户反馈单人在场景内流畅，敌军和友军开始移动后变卡。v31 用户实际首关日志中，5 秒窗口实际帧率曾降至约 19–26 FPS；物理更新 P95 约 13–14 ms，画面更新 P95 达 22–55 ms。Laya 请求和响应均为 0，因此当前问题不能归因于 Laya 服务。

已查到墙体局部受击仍会触发原整个区域的 SurfaceTool 合并，这是交火长帧的确定来源。它不能独立解释所有纯移动卡顿。对复制的单位数据执行独立运动数学和原骨架采样，60 人移动/承托查询约 3.1 ms，完整骨架动作约 8 ms；正式运行已有 NPC 30 Hz 交错物理、24/6 Hz 视觉采样及 1.8 ms 动作预算，不能把这两项测试简单当作每帧实际占用。

## 本次实现

- 普通首关墙体使用持久 ArrayMesh，每个墙格保留独立顶点与索引范围。受击只更新该格；打穿时同时更新相邻面的显露。保持原墙格耐久、裂纹、弹痕、局部破口及坍塌，房屋专用剖切逻辑保留。
- 84 种武器在加载时准备原始几何及原节点 PackedScene 缓存，换装/增援复用模板。手持武器通过 GPU 几何图集与实例批次绘制，枪口、抛壳、握点及原动作节点继续有效。
- HUD 保留原控件布局、字体和输入；缓存未变文字的网格，静态面板不因计数改变重建。
- 人物移动的车辆碰撞及承托查询先用包含所有真实车体/炮塔部件的保守半径排除远车，再执行原精确形状检查。没有关闭人车碰撞或减少战斗人数。60 人复制数据的运动数学测试约降至 2.6 ms，该数字为跨次微基准，不能据此承诺实战收益。
- 原骨架的恒等旋转不再重复写回骨骼。角色身体/头盔继续使用 source-rig-soldier.glb 的原模型、蒙皮及动画；全项目没有改成全 GLB 离线资产流程。
- 运行日志增加每阶段分位数、最慢帧的完整阶段记录、移动/开火单位数和局部墙格上传量，用用户真实试玩定位剩余问题。
