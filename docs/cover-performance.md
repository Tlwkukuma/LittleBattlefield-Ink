# 掩体规则的性能约束与第一批实现

2026-09-28。用户确认掩体方案，并明确要求控制计算消耗。本文件是 [统一规范](cover-combat-spec.md) 的实施约束。

**v2026.09.28.36 行为更新：** 用户要求 AI 按方向射击、减少精准身体选点。首关现为每次观察最多 4 名候选、每名一条轮廓视线；取消开火时二次确认及头胸选点，改用有限时效的观测位置和带误差方向。下文第一批的“双点观察 / 精确选点”是历史记录，以 [方向射击实现](ai-directional-fire.md) 为准。实际枪口、命中胶囊、掩体和破坏保持原规则。

## 当前已接入

1. `combat_pose.gd` 复用原角色已经计算的身体胶囊和枪口，不再次采样动画、计算 IK 或加载模型。AI 观察、直接瞄准读取这些实际部位；假设站位用原骨架静态测量高度。姿势缓存跟随原有 24 / 6 Hz 视觉调度；实际开火仍沿用原先即时求真实枪口和墙体碰撞的路径。
2. 观察与开火选点分别保持最多两条遮挡射线。观察先检查头部，再按需检查胸部，避免低墙场景中大量本可一次结束的查询。最终弹丸命中仍精确执行；决策使用的旧观察数据不赋予透墙追踪能力。
3. 原来只返回目标高度的 AI 瞄准现在保留实际三维命中点，包括卧姿/动作造成的水平偏移。选掩体不再把 1.02 米当作完全蹲伏遮蔽高度，改用原骨架头顶基准。
4. `cover_rules.gd` 从 `data/cover_rules.json` 只解析一次，为 16 类材料、84 项随身武器、17 个车载/固定武器模式预编译查表数组。组件和武器在加载时绑定；每个物体只持一份共享配置引用，不复制整套响应表。
5. 保留已有 `pending_rebuild` 字典按物体 ID 合并网格更新。物理命中状态立即改变，显示更新不按每颗霰弹重复提交同一面墙。

**当前已在第一批基础上启用墙格枪弹/近战结构伤害和材料禁破规则。** 具体范围见 [墙体枪弹修正](cover-kinetic-runtime.md)；整体道具正值耐久、连续材料穿透、爆炸多层传输和可变土体仍待迁移。下文“本轮检查”保留第一批的历史记录，不能代替第二批检查。

## 硬性约束

| 系统 | 控制办法 | 不能用于“省性能”的做法 |
| --- | --- | --- |
| 材料与弹药 | 初始化预计算；命中只按整数索引查数组 | 每颗弹解析 JSON、按名称正则推断材质、复制大字典 |
| 实际子弹 | 沿用空间索引和局部网格；仅命中材料时计算出入口，穿透最多 4 层 | 所有弹丸每帧扫描整张地图或全部墙格；漏算/延迟已发生的命中 |
| 骨架 | 复用原有姿势结果，开火沿用已有即时枪口求解 | 因一次 AI 视线查询重算双方动画或全身 IK |
| AI 决策 | 继续使用已有共享 2000 μs/tick 预算，掩体搜索已有约 650 μs 单次预算；分帧推进和缓存 | 给新掩体系统再叠一份 2 ms 预算；每个 AI 每帧全方向多点扫描 |
| 实际命中 vs 决策 | 决策允许预算内延期，最终弹道/碰撞执行当前物理状态 | 把 AI 搜索预算套在子弹命中上，令超预算子弹穿墙 |
| 破坏与支撑 | 按受损格/物体收集；同帧同物体合并；只有拓扑变化才重算支撑/导航 | 每个弹痕重建整屋；对整张地图重建导航 |
| 爆炸 | 先空间筛选半径内对象，再作便宜距离剔除，最后对实际受影响对象作遮挡 | 为远处所有单位发爆炸遮挡射线；每个碎屑二次产生完整爆炸 |
| 土体侵蚀 | 只处理受影响地形块，共用材质/高度数据；受影响区去重 | 全图重建地形、每粒沙建一个刚体、显示与碰撞用两套地形 |
| 表现 | 少量实体残骸、大量有上限的表现粒子；合批与复用 | 第二台世界相机、逐弹动态灯光、永久不断累积的碎屑 |
| 超负荷 | 降低/合并可省的粒子、延后非紧急 AI 决策 | 隐藏敌人真实暴露、放弃碰撞或让破口暂时仍挡子弹 |

650 / 2000 μs 是当前 AI 调度的检查预算，不是操作系统保证的硬实时上限；单个原子几何查询仍可能越过剩余预算，因此必须同时控制候选数量和单查询范围。后续新系统不能以“用了时间预算”为理由无限增加一次查询的工作。

## 后续重型改动的准入条件

- 单独记录 `material_hit_us`、`penetration_queries`、`blast_candidates`、`blast_rays`、`terrain_dirty_cells`、`mesh_rebuild_count` 和 `support_dirty_count`；计数/计时仅在性能记录开启时收集，正常模式不创建逐弹日志。
- 命中与地形修改保持确定性，不以本机每帧剩余时间决定本次伤害多少。若地形事件预计超过预算，先分解为有明确上限的局部块事务；同一事务的地形高度、弹道和承托同时提交，不能在过渡期间各用一套状态。
- 限制脏块集合为地图已有块数量，合并同一区域的重复工作，按事件顺序保留伤害；不能因队列满而丢弃墙体破坏。超载先削减表现，必要时减少单次爆炸的表现细分，实际体积预算不变。
- 开始实现可变地形前，先有固定几何/侵蚀数学夹具的微基准。若局部更新已超过目标预算，优先减小影响遍历范围、合并重复查询，而不是扩大帧预算。
- 对同一机器、同一构建配置、同一场景比较；先修复新增开销，再接下一批机制。完整 50 vs 50 的物理耗时 p95 增长目标 ≤10% 是正式用户试玩性能记录的门槛；不能用空场 60 FPS 冒充通过。

## 本轮检查与结果

- `qa/cover_foundation_contract.gd`：119 项注册表、实际身体采样、瞄准偏移、最多两条射线与单次配置加载检查通过。
- 原壕沟 49 项几何/原骨架检查、战役执行 14 项检查通过。没有自动操作游戏。
- 初次并行跑多个检查污染了计时，保留原始结果作记录，没有作为性能结论。不同会话也在修改共享工程，跨进程的早晚两次全项目微基准不能单独归因于本改动。
- 使用 `qa/cover_query_cost.gd` 在**同一进程、同一冻结世界**交替比较旧观察策略与新策略：60 个单位、1800 对候选，每种策略 15 次。两者均为 129 条实体射线；中位总耗时由 11.460 ms 到 11.974 ms，增加约 4.5%。这是整批候选查询耗时，不是每帧耗时，也不是 50 vs 50 FPS。
- 该比较使用由静态测量构造的胶囊，不播放动画、不推进战斗、不发射武器、不调用远端模型。[原始结果](../qa/performance/cover-query-cost.json)。
