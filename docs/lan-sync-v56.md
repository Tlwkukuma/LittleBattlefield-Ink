# v2026.09.30.56–57 联机状态、间歇卡顿与车辆姿态

用户确认 v55 已能加入，但仍有间歇卡顿，并要求左上角显示 FPS / Ping。

## 实施

- `network_status_hud.gd` 独立轻量 Label，左上角 14 / 12 px，忽略鼠标，4 Hz 更新。FPS 取统一场景连续帧计数；关闭 Debug 也计数，不开启详细 CPU / GPU 采样。Ping 读取 ENet 对端可靠包 RTT（ms），不是帧间隔或输入回声；房主为已连接队友最大值，离线显示 --。状态断档超过 250 ms 会额外显示等待时长。
- 原 IPv4 pump 在引擎默认 ENet poll 之后运行，回复已转到本地 socket 仍需等下一帧才读，ENet 新发的输入也只能在 poll 后转出。现在统一单 MultiplayerAPI 禁用自动 poll，由优先级 -100 的 LanSession 执行“IPv4 接收 → ENet poll → IPv4 发出”，先于战斗呈现；没有在后台线程操作场景或同时重复 poll。
- 同一帧收到多份 owner 状态，只留最新房主时刻；解压、深拷贝与真实碰撞重放只做一次。普通单位运动与结构、背包等可靠快照仍按原规则更新；没有为追求速度丢弃破坏修订。接管和退出清空积压状态。
- 退出仅单向转出 disconnect，不再把远端回复喂入已关闭的 ENet socket。已载入第一关时重连复用该场景，不再重复重建。
- 每 5 秒连接日志记录真实 ping、owner 断档、poll / 校正 / 快照耗时以及输入回声 / 更新 P95。日志使用同一个 `user://lan-connection.log`，含版本 / PID，便于区分网络迟到和本地处理尖峰。

引擎顺序与 RTT 定义核对自 [Godot 4.6 SceneTree 源码](https://github.com/godotengine/godot/blob/4.6-stable/scene/main/scene_tree.cpp) 及 [ENetPacketPeer 文档](https://docs.godotengine.org/en/4.6/classes/class_enetpacketpeer.html)。额外一帧等待是对原项目调用顺序的分析；尚不能据此认定用户全部卡顿只有一个原因。

## 验证

- `qa/lan-v56-runtime.log`：100 份突发 owner 状态只校正一次，保留最新输入确认；实际人物碰撞、房主 / 队友 60 帧移动一致、枪塔只预测呈现、弹体时间单调、重排碎片仍通过。
- `qa/lan-v56-ipv4.log`：回复源端口被改写后可归一化，关闭后端口可重新绑定。
- `qa/lan-v56-native-*.log`：本机经真实 IPv4 接口 192.168.22.23 进入运行中战役，蓝军 27 号，破坏修订 2，移动 2.165 m，28 次权威射击，471 个运动分包；退出后模式 offline / socket 清理并继续跑帧。HUD 实测 `FPS 75 | Ping 20 ms`。此测试是本机接口回归，不是跨电脑实战 Ping。

现场 v55 PID 2140 已在 16:36:26 成功加入真实 192.168.23.181；16:37:47 记录主机断开。后续 v56 诊断加入收到“当前战役已结束”，因此持续跨电脑验证需要房主重新开始并开放战役。Windows Responding 瞬时状态曾在 true / false 间变动，不能仅据该属性认定主线程永久死锁。

房主重新开始后，冻结 v56 PCK 的实际跨电脑诊断连续运行约 35 秒，Ping 16–19 ms，自身更新 P95 约 40–41 ms，输入回声 P95 约 40 ms（早期窗口曾为 54 ms），随后主动退出，stop 返回并正常结束。见 `qa/lan-v56-real-metrics.log`；这次是无操作诊断，不能代替用户驾驶 / 射击时的长期卡顿验收。

## v57 车辆朝向

用户截图显示其他玩家的车辆保持固定朝向滑动。代码定位：`Dimensions.body_basis` 总是优先取离线初始化的 `pose_basis`，原网络字段只传 angle、不传此缓存，因此更新 angle 仍不改变实际车体显示。

v57 快照补全真实车体 basis、前轮转角及倾斜 / 角速度；同 v57 实时车行明确携带 12 浮点（原 6 项加姿态四元数、前轮转角、yaw_rate）。旧端仍收到 6 项；新客户端接旧房主则从传来的 angle / ground.normal 重建车体 basis。不能用速度方向作为车头方向，避免倒车 / 漂移显示反向。晚到的旧快照不得覆盖新的 basis / 转角。

`qa/lan-v57-runtime.log` 验证旧 6 项车行转向 90°能更新实际渲染 basis，新 12 项恢复带坡度和侧倾的姿态与前轮转角，旧可靠快照不会回滚。还保留原本地预测碰撞与突发合并验证。

## 最终发行与边界

冻结 v57 发行窗口 PID 10456，实际启动时间 2026-09-30 17:10:12，Godot 4.6.3.stable.official.7d41c59c4，统一第一关 / 局域网入口；17:10:23 加入真实房主并接管 1 号蓝军，后续连接日志持续推进。Ping 20–21 ms，自身更新 P95 40 ms，典型快照应用 1.5–1.8 ms。部分时段输入回声 P95 上升但 Ping / 更新间隔保持稳定，尚不能认定所有间歇卡顿已消失；该指标还受房主是否持续应用此单位控制影响，需要结合实际死亡 / 接管 / 移动状态判断。

`qa/lan-v57-final-latency-*.log` 在 IPv4 通道、每方向 35±12 ms、5% 随机丢包及一次 1 秒下行中断下恢复更新，恢复后的状态年龄 P95 约 50 ms；同物理帧预测回应 0–1 ms 并非显示器输入延迟为零。第一次 v57 比较因 Python 测试转发程序未处理临时探测端点关闭后的 Windows UDP ICMP reset 而提前停止，已排除该结果并修复测试程序。v55 对照的中断发生在不同加入阶段，不能将两组总状态年龄直接作为优化百分比；因此不报告未经匹配的速度提升比例。
