# v2026.09.28.39：墙体切面尖峰与重复渲染工作

本次目标仍是首关密集交火稳定 60 FPS、战斗 Draw Call 小于 50。**以下离线结果不能证明此目标已达成**。沿用 30 对 30 人数、原骨架和动作、真实弹道/地形/可破坏墙体，不改变物理或 AI 更新频率，不降低分辨率及模型细节。没有新增全局性能规范。

## v38 用户实玩证据

来源：`qa/performance-v2026.09.28.38-20260928-162804-197.log`。

- 密集阶段多个 5 秒窗口约 51–56 FPS；用户截图为 46 FPS。平均值不足以表示流畅程度。
- 玩家进出建筑时，墙体切面一次变更 38–240 格；已记录单次墙体 CPU 工作约 9–18 ms。墙体切面与真实损伤走了同一条重建路径，造成明显尖峰。
- Draw Call 部分战斗窗口超过 50，不能把截图的一帧 49 当作完整验收。
- 单位移动仍重复查询当前地面高度；已被 GPU 合批替代的源 MeshInstance3D 仅设置 layers=0，仍接收变换通知。
- 武器图集每个实例至少提交 24,576 个顶点，实际小枪仅使用前缀；屏幕外武器仍进入整图批次。

## 实现

1. `wall_batches.gd` / `retained_wall_surface.gd`：预生成完整墙和 1.15 m 剖面的精确几何及上传字节。纯视角切换直接选择缓存。HP、弹痕、存活状态或邻格暴露改变时，立即使相应格的两种缓存失效。真实破坏、碰撞和同帧上传保持原顺序。
2. `batched_source.gd`：停用已被替代的源 GeometryInstance3D 的渲染变换通知。节点、全局变换、骨架和挂点仍保留；实际批次与主角遮挡副本继续更新。接入人物、挂件、武器、刚性碎片和枪口焰的现有批次。
3. `weapon_instance_batches.gd`：同一批次只提交当前可见武器中最长的实际顶点前缀。不同前缀网格预热并复用，沿用原有材质/批次分组。正交视图按完整模型包围体作保守裁剪，不只检查模型原点。
4. `proving_world.gd` / `terrain_surface.gd`：移动子步缓存当前高度与局部状态，共用坡度判断；经过保守扫掠确认仅有地形时省去重复障碍物检查。重叠恢复仍先执行，随后重读其可能改变的位置与速度。
