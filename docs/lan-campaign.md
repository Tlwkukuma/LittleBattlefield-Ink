# 首页与战役中的局域网协作

v2026.09.30.53 深度修复队友移动调度、网络控制呈现和快照排队：远程人类与房主按相同 60 Hz 更新；双方新版使用独立 30 Hz 实时通道、本地碰撞预测和房主应用序号校正，完整可靠快照最多一个在途。与旧版本继续互连，但双方 v53 才启用全部优化。详细根因、丢包对照和回归证据见 [v53 同步定位](lan-sync-v53.md)。下方版本记录保留各版实施历史。

原生 Godot 项目仍从 `res://proving_ground.tscn` 启动。无命令行测试参数时显示沿用旧版小小战地结构的首页：浅蓝网格背景、原版标题美术、深蓝战术纸面板和三枚主按钮。「战役」进入石墙果园；「局域网协作」打开同一界面内的房主开放与队友加入页面；「联合演武场」保留原验收入口。战斗右上角「战役菜单」可再次打开首页。房主在已经进行的战役中按「开放当前战役给队友」，会继续模拟同一场战斗，不重建关卡。尚未进入战役时，此按钮先进入第一关。

v2026.09.30.45 修复战役开始后返回菜单只剩标题图、按钮和文字空白的问题。首页、局域网页切换与关闭后重开时重新创建当前可见页，保留局域网连接状态；`qa/lan_after_campaign_capture.gd` 从第一关回到菜单并打开局域网页，检查实际渲染的按钮。

v2026.09.30.46 修复跨电脑房间搜索：扫描从每个私有 IPv4 接口发送广播，兼顾多网卡，并对已知房主 IP 发送 UDP 27830 定向查询。玩家在输入框填房主 IP 后点「刷新」会保存地址并让该房间进入列表；之后重开游戏也会自动定向搜索。发行包可在 `host-address.txt` 预填房主 IP。未知的跨网段房间无法靠广播凭空发现，须输入一次房主地址；房主换 IP 时要更新地址。没有回包时列表会显示明确的空状态。

v2026.09.30.47 将版本号与战役协议兼容性分开。v45、v46、v47 的战役 RPC 与快照字段未变，房间列表允许这三个版本互相加入；新版客户端连接旧房主时按房主版本握手，旧房主拒绝未知版本时可按其回报版本重试一次。新版房主接受这批旧版本并回传客户端请求的协议版本；未知版本仍拒绝。已对 v45 房主实测：v47 客户端通过版本检查，随后因房主当前无存活的空闲蓝军被拒绝；完整进入战场尚未验证。房主需有一名可接管的存活蓝军。

v2026.09.30.48 修复无空闲蓝军时无法进入战役：房主先找现存蓝军；没有时从阵亡蓝军槽位按原增援与出生点规则恢复一人，再将其分配给队友。即使预备兵力已用尽，也允许本次加入所需的一个增援名额；使用已有单位 ID，客户端初始快照结构不变。若既无阵亡槽位也无安全出生位置，仍给出明确拒绝原因。加入连接失败或被拒绝后返回局域网页，不让本地预加载的战役误留在后台。`qa/lan_join_reinforcement_host.gd` 与 `qa/lan_compat_smoke.gd` 双进程验证 29 名蓝军 AI 全阵亡、预备兵力为 0 时仍成功加入蓝军 2 号，房主和客户端均确认；跨电脑真实加入需要两台电脑均运行 v48，因为旧房主无此补位逻辑。

v2026.09.30.49 修复队友机卡顿的两条明确开销路径：战役快照原样经可靠 RPC 每 0.1 秒发送，正常首关约 60 KB，100 个受损物件时约 87 KB；现在新版双方使用 FastLZ 压缩，样本 87,444 B→5,941 B，压缩 70 μs。旧版客户端仍接收原格式，新版客户端也接受旧房主原格式。客户端建立物件 ID 查找表，按修订号只对真正变化的物件排队重建，同一批 100 个受损物件重收时从 100 次待重建降为 0。双进程战役测试确认进入、持续快照、破坏修订、姿态、移动与射击；尚待用户在两台实际电脑确认画面帧率与网络延迟。

v2026.09.30.52 针对“75 FPS 但联机动作慢”增加小包移动同步：新版房主每 0.05 秒发送士兵和载具位置，小包按最多 16 名单位拆分，使用原有不可靠有序事件通道；生命、弹药、据点、破坏等完整状态仍每 0.1 秒走可靠快照。客户端按房主时间拒绝旧移动帧，较旧的可靠快照只更新非移动字段，避免排队快照把人物拉回；画面在两次网络更新间按权威速度短时推算，角色真实命中位置仍由房主决定。旧版房主保持原 0.1 秒快照，v52 队友端也能在画面上短时推算；双方更新 v52 才有 0.05 秒移动帧。双进程新版测试收到 346 个小包，并验证姿态、移动、射击、物件破坏以及旧可靠快照不会回滚新位置；v52 队友与 v49 房主也实测完成加入、姿态、移动、射击和破坏同步。若链路有实际丢包或卡顿，仍需用两台真实机器复测。

队友在首页的「局域网协作」页会自动搜索同网段及已知地址的房间。房主开放战役后在 UDP 27830 回复查询，列表显示第一关、房主地址、人数和项目版本；点击同协议兼容且未满员的房间即可加入，房间关闭或失联约 7.5 秒后从列表移除。「刷新」可立即重查。仍可输入房主显示的局域网 IPv4 地址（游戏端口默认 27829）手动加入。客户端先加载同一关卡，再连接房主；连接后接管一名存活、无人操作的蓝军士兵或获得一个增援蓝军。v45 至 v52 沿用同一 RPC 签名；旧房主缺少 v48 的加入增援，双方运行 v49 或更新版本才使用压缩快照，双方运行 v52 才启用小包移动同步。最多接入五名队友，游戏连接使用 UDP 27829；跨网段、防火墙或 VPN 路由需要由玩家自行保证可达。局域网广播不能穿过通常的路由器网段边界，因此需要已知房主地址进行定向发现。

`lan_session.gd` 使用房主权威模拟：客户端发送移动、瞄准、射击和菜单动作，房主计算 AI、弹道、伤害、占领、载具和破坏，再同步士兵、载具、弹体、据点、改动过的墙格与背包。初始快照包含已发生的破坏；客户端确认关卡准备完成后才开始连续快照，避免关卡构建期间排队造成掉线。队友阵亡后可接管下一名存活蓝军；断线后原单位交回 AI。普通射击、载具、姿态、配装、医疗与拾取动作走同一战役规则。

验证入口：`qa/lan_join_smoke.gd` 分别用 `--lan-smoke-host` 和 `--lan-smoke-client` 在两个 Godot 进程运行。它验证进行中加入、初始及后续破坏同步、姿态命令、持续移动和房主权威射击。该脚本不会打开用户验收窗口；交付验收仍使用项目正常首页与第一关。

房间发现验证：`qa/lan_room_smoke.gd -- --lan-room-known=<房主 IPv4>` 会打开正常首页的局域网页并检查指定房主在房间列表中。2026-09-30 从 `192.168.22.23` 对 `192.168.23.181` 的 v45 房主运行此检查，实际收到 `192.168.23.181:27829` 房间并显示在列表；这验证 UDP 发现与 UI，不代表 v46 游戏握手已经跨电脑实测。
