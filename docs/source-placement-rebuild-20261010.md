# 源关卡部署恢复（2026-10-10）

这是基于当前远端源码重建的修复，不是旧丢失提交的恢复，也不沿用旧测试成绩。验收只初始化实际世界、读取碰撞和规则状态，不调用世界 step、AI update、移动或开火；实际战斗继续由用户操作。

## 首关地图与入口分离

离线十章战役全部经过 `campaign_source_layout.gd`。第一章不再经过 `orchard_level.gd` 的后续果园改版：实际 world 恢复原 `3300 × 2100` 源单位（`82.5 × 52.5 m`），地物、原始道路、实例、树木、车辆、控制点中心及出生坐标共用同一原始坐标系。玩家和蓝/红士兵原 ID、朝向、初始人数、最大人数和总兵力保留。

源第一章保留每方十个出生锚点；其他章节严格保留各自源数量，不为凑十个删除或虚增。例如第六章为 5/5，第七章为 14/12，第九章为 6/10。源第一章只从已验证 `level01_rules.json` 复用装备和规则，装备按原单位 ID 绑定。其他章节继续原先明确标注的缺失运行时配装兼容层。

LAN 和原果园演练仍通过 `orchard_level.gd`，没有修改其布局、地形或入口。`source_layout` 标记使源第一章使用自己的公开出生点到控制点路线，不再要求走另一张地图上的改版果园壕沟。`data/original` 文件不改写。

## 有界、完整、可审计的实体放置

`campaign_placement.gd` 用实际 `world.blocked()` 的地物、真实载具与世界边界，以及地形坡度和人员间距检查候选位置。站立检查为半径 0.31 m、高 1.95 m，人员间距为原来的 0.72 m。先为所有合法原位置保留位置，再处理冲突，避免早期纠偏抢占后续本来合法的原出生位。

仅不合法的原位置会搜索邻近位置：12 圈、每圈半径增加 0.36 m、每圈 24 个方向，最大距离 4.32 m、至多 289 个候选。找不到合法点就明确失败，绝不退回非法原点。每名实际角色保留 `campaign_source_id`、原始 `campaign_source` 和 `spawn_placement`；`placement_report` 包含原点、实放点、位移、原因和尝试数。原因区分越界、实体碰撞、坡度、已占用位置。

先预检完整名册，然后一次性创建；人数不合法或任一人员放不下都不提交部分名册，不循环复制缺失人员、不以 maxActive 截短兵力。装备和初始朝向在提交后沿原单位绑定。

## 失败接口与加载回滚

- `CampaignRules.configure(world) -> bool`
- 初始失败：`campaign.phase == "placement_failed"`、非空 `reason` 和 `last_spawn_failure`，`campaign.active == false`
- `World.setup()` 保持返回 compiled Dictionary，在返回值与 world 上提供 `setup_ok`、`placement_report`、`last_spawn_failure`
- 失败世界没有部分单位名册或玩家、不启用 AI；加载事务据此保留旧世界和旧阶段，不推进战役进度
- 增援失败返回空 Dictionary，保留原死亡人物的全部状态、预备兵力、已部署数及补员游标，并通过 `last_spawn_failure` 和 `spawn_failed` 事件报告；成功重生继续原单位 ID/源朝向，更新实放记录与所选源锚点，且小队后续成员仍从原锚点搜索，不能逐次纠偏漂移
