# 果园 B 点：院内指挥所

2026-09-29 / 布局第 7 版。用户要求占领位置参考《战地》重新制作。

参考 EA《Battlefield V》[Squad Conquest 官方说明](https://www.ea.com/games/battlefield/battlefield-5/news/squad-conquest) 中明确的进攻路线、掩体和有战术意义的旗点布置。本项目采用下述院落设计，不声称照搬原作规则或资产。

## 布置与反馈

- B 点位于四栋房屋之间的院心，源坐标 `(2640,1040)`；约 4.6 m 的实体旗杆、绳索与低矮石座构成识别地标。旗布随现有控制进度降下 / 升起，蓝、红、灰分别表达双方与中立。旗杆是非阻挡目标标志；不能被误当作掩体。
- 占领范围约 10×9 m，用削角多边形贴合院内空地。近处显示短地面虚线，远处关闭；视觉边界和实际人数判定读取同一多边形。屋顶、地下及范围外的建筑 / 院外区域不计入占领，垂直容差为旗点地面上下 1.8 m。
- 西侧原机枪与沙袋作为进攻入口的争夺位置。西南、东北各增一组错开的低木箱，分别高 0.85 / 1.0 m，使用现有可破坏道具与真实挡弹 / 通行数据；保持入口至院心、南侧与东侧占领位置可达。没有新增围墙缺口和道路。
- 四栋房屋的地面底板重新跟随实际建筑位置，清掉此前遗留在院心的褐色矩形。旗座周围仅有一圈小型碎石地坪，不给整个占领区域铺巨大色块。
- 撤下原来的巨大世界文字及圆圈。顶部原兵力条下使用紧凑 B 点卡片显示名称、状态、距离或占领百分比；进度条读同一规则值，双方在场时显示“争夺中”。正常界面的 Debug 仍默认关闭。

## 规则与资源边界

`orchard_objective.gd` 负责作者布局，`capture_zone.gd` 共用于规则和显示。现有增援、胜负条件、占领速度与双方争夺计算保持不变；本次没有改为多旗点征服模式。

`objective_flag.gd` 将旗座、旗杆、绳、旗布和区域短线合为一个 1,092 顶点 / 364 三角形网格、一张不透明材质。旗布由 GPU 做小幅摆动，进度与颜色最多沿现有 10 Hz 概览刷新，不使用布料物理、额外光源或全屏后处理。顶部卡片复用既有 HUD 图形和文字批次，不增加随镜头移动而每帧重建的屏幕标记。

## 验证与验收

`qa/capture_objective_contract.gd` 冻结原入口，检查院内 / 院外 / 跨高度占领、入口至分散位置的几何连通、真实可破坏低掩体、旧地板位置清理、旗帜资源和五档控制状态。`qa/orchard_layout_contract.gd` 同时检查原机枪 / 中立吉普、南墙封闭、现有路线。

本次结果：据点检查 36/36，布局检查 198/198。v2026.09.29.22 GPU 冻结资源夹具正常入口 26 draws，现有夹具的多倍率 / 武器替换 / 特效资源组合最多 45 draws，shader 无报错，世界时间和射击数始终为零。此夹具未同时激活所有爆炸、弹坑状态，不是任意实战负载的上限。日志在 `qa/performance/capture-objective-contract.log`、`orchard-objective-layout.log` 和 `orchard-objective-gpu.log`。

编译、几何和冻结渲染检查不代替实战。用户在首关按 Tab 开始，走入果园 B 点，验收入口识别、掩体交战、占领边界和旗帜反馈。
