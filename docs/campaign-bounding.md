# 首关小队交替跃进

2026-09-30 补充：本文记录 v2026.09.30.51 的历史简化开火窗口，不能视为完整交替掩护或效果验收。v2026.09.30.55 已由 `campaign_maneuver.gd` 的到达/交接状态机替代，见 [当前实施记录](campaign-ai-3d-runtime.md)。下面的频率、窗口与 QA 命令分配描述属于旧版；旧模块仅保留纯函数回归，当前运行检查使用 `qa/campaign_3d_contract.gd`。

对照旧 Pixi 项目最新的 `docs/ai-commanders.md`、`src/campaignTactics.js` 和 `server/CampaignBattlePlan.mjs`（截至 2026-09-30）：原版已退役 Laya，使用红蓝独立的 Node 数值指挥器。18 个战术原型、30 关各三种蓝方方案；第一关蓝方 T01 中突双牵、T02 右墙爆破、T03 林翼迂袭，红方固定据点双翼。路线阶段、局部交火与效果证据分层处理；历史实验不能当成效果验收通过。

Godot 当前指挥层仍以 0.5 秒周期分组、下达攻／守／警戒／支援／预备任务，单兵使用有界感知与寻路。本次补入一个通用的“小队真实火力开窗”执行机制，供默认及可选指挥模式共用。仅在攻点小队采用 bounding、至少两名附近队员、一人确有最近 1.15 秒射击且有 1.3 秒内目视报告时，指定这名队员掩护，其余队员保持原推进任务。窗口最多 2.4 秒；掩护失效立即解除，同一人再次开窗至少隔 0.9 秒；进入旗点周围 5 米时由夺点优先。小队任务、真实弹道、射界、伤害、墙体与路径不变。

该机制复用原开火事件、已有目视报告和 0.5 秒指挥周期；不做新射线、全队找敌、逐帧路径规划或额外场景节点。只在开窗时发一次 `ai_bounding_window` 诊断事件，不能把事件数当作攻点成功。

验证：`qa/campaign_bounding_contract.gd` 检查新鲜射击开窗、过期失效、冷却、听觉报告不能冒充目视、孤立射手、旗点优先及真实首关小队命令分配；`qa/orchard_layout_contract.gd` 检查原布局和无战斗模拟启动。战术效果、胜率与战斗帧率仍须用户实战验证。
