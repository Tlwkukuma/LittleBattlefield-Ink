## 从哪里开始

默认主场景仍是 `res://proving_ground.tscn`，启动后进入首页：

1. 选择 **战役**，进入“十章战役”页面
2. 选择已解锁章节和战术，进入关卡
3. 开战前先看简报和配装；按 **Tab** 关闭面板开始战斗
4. 胜利后解锁下一章；失败可重试本章；第十章胜利显示战役完成

首页还保留 **联合演武场** 和 **局域网协作**。局域网继续使用原第一关果园战役，与离线十章进度分开；联机结果不会解锁离线章节。本轮没有完成双机联机验收，不把单机检查当作联机通过。

章节依次为：石墙果园、装配厂区、洪泛草甸、双街小镇、干溪通道、要塞内院、林间路口、城郊医院区、芦苇湿地、谷仓村落。

## 启动方式

### 源码项目

用 **Godot 4.6.3 stable** 导入 `project.godot`，运行主场景；也可执行：

```sh
godot --path .
```

Windows 的 `START_GAME.bat` / `START_RANGE.bat` 使用本机 Godot；若默认路径不同，先设置 `GODOT_EXE`，或直接通过 Godot 导入。角色、美术与音效资源已包含在源码中，普通运行无需重新下载素材。导出发行版另外需要同版本官方导出模板。

### Windows 便携发行包

最终 Windows 运行包生成后，完整解压 ZIP，运行 `LittleBattlefield.exe`；`LittleBattlefield.pck` 必须与它同目录。该发行包不要求玩家安装 Godot。LAN 启动器是可选入口，防火墙辅助脚本只由玩家在需要时自行运行。

当前 v2026.10.09.3 Windows 候选包已导出，22 个 ZIP 文件与 1,185 个 PCK 条目通过完整性检查。相同 PCK 在隔离目录中由官方 Linux release 模板完成默认入口、第四章和第十章的短启动检查，章节简报保持 simulation_time=0。**Windows EXE 尚未在 Windows 实机运行**；这也不是全关战斗试玩。最终归档还会刷新验证文档。

## 常用操作

- WASD 移动，鼠标瞄准，左键射击，右键扩大观察/瞄准范围
- Shift 快跑，空格跳跃/翻越，C 蹲伏，Z 卧倒，R 换弹，B 切换射击模式
- 1–3 武器位，4 战术装备，5 医疗；按住 G 打开装备轮盘；战斗滚轮切换武器
- E 通用交互，F 上下车或接管/离开固定武器；Tab 配装、附近掉落或战役战术面板
- F5 重开当前场景；右上“战役菜单”回到首页/章节页
- 载具 W/S 前进/倒车，A/D 转向，Shift 渐进加速，空格手刹

联合演武场保留武器、载具、地形和角色检查入口。场景工坊支持 JSON 打开/另存、撤销/重做；本轮新增导入前校验，坏 JSON 不先替换当前场景。

## 进度保存

离线战役只保存已完成章节、当前选择章节和战术，文件为 Godot 用户数据目录中的 `campaign_10_v1.json`。它不保存进行中的战斗、玩家当前位置、弹药或墙体破坏；关闭程序后重新进入本章会从开战前开始。

保存采用临时文件与备份恢复，使用独立命名空间，不覆盖旧进度文件。若保存失败，界面会提示；不要把“仍可继续当前战斗”理解为进度已经落盘。

## 校验、版本与交付

唯一项目版本定义在 `scripts/proving_ground.gd` 的 `BUILD_VERSION`。运行窗口还显示启动时间/PID；Godot 引擎版本与项目版本不是同一个值。

当前已完成静态/纯数据检查，包括原场景数据对照、章节进度规则、编辑器非法数据拒绝，以及交付工具的多版本/重复打包/散列/防旧房主地址泄漏测试。完整战斗试玩、十章平衡、Windows 实机运行、双机联机和本轮性能结论仍需分别记录，不能由这些检查推断。

```sh
python tools/test_validate_delivery.py

# 只检查导出前提，不生成游戏包
```
